# Markdown Article Reflection 

## Article
- **Title:** [The Eternal Truth of Markdown](https://www.wired.com/story/the-eternal-truth-of-markdown/)
- **Author:** Scott Gilbertson
- **Publisher:** WIRED
- **Published Date:** June 24, 2024

## Reflection 
I don’t think I had ever used Markdown before. I did have some experience with LaTeX in my math class, since it helps a lot with formatting symbols and equations. Although LaTeX made my homework cleaner, it took me a long time to learn the right commands. So when I first saw my professor’s notes about common mistakes and expectations for Markdown, I was scared because I thought Markdown would be more complicated than LaTeX. 

It turned out to be the opposite. According to creator John Gruber’s syntax guide,
> “A Markdown-formatted document should be publishable as-is, as plain text, without looking like it's been marked up with tags or formatting instructions.”
>
> — John Gruber (quoted in the article above)

As I’m completing this assignment and writing this paragraph, I can see what he means. Markdown feels simple and straightforward. It also doesn’t feel like a completely new syntax system, since some of its basic commands I’ve already seen in somewhere else. Just like the author points out,
> "The simplicity and flexibility meant I would live the dream of write once, run anywhere."
This feels especially relevant for our class because we’ll have a lot of collaboration on projects. I think Markdown will make it easy for a team to maintain one clear README file for anyone who is reading.
